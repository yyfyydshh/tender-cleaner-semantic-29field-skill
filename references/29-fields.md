# 29字段语义口径

公告正文优先于标题和列表元数据。字段没有原文依据时填空；不要从常识、平台首页或相似公告推测。金额单位统一为人民币元。

| 字段 | 语义来源与规则 |
|---|---|
| 原标题 | 原始标题列，不改写。 |
| 来源链接 | 原始链接列；缺失时仅使用正文中明确出现的 `http(s)` URL。 |
| 项目名称 | “项目名称/工程名称”优先；否则标题去“招标公告、采购公告、结果公告”等后缀。 |
| 招标编号 | “招标编号/采购编号/项目编号”优先；其次原始编号列。 |
| 项目执行地址 | 交货、工程、建设、施工、实施、服务地点；不能把投标递交地点误作项目地址。 |
| 项目规模 | 项目/工程/建设规模，总建筑面积、建筑面积、占地面积、明确需求数量、供货区域等；保留数量与单位。 |
| 招标范围 | “招标范围/采购范围/招标内容/采购内容”；无标签时提取“现对……进行招标/采购”中的对象。 |
| 项目工期 | 计划工期、工期、供货期、服务期限、合同履行期限、交货期。 |
| 招标金额 | 预算、最高限价、控制价、招标控制价；转换为元。排除标书费、保证金、代理费与数量。 |
| 获取招标文件时间 | 仅从“招标/采购文件获取、售卖、发售”语境提取的日期或时间范围。 |
| 投标截止时间 | 提交/递交投标或响应文件截止时间、投标截至时间；可使用独立元数据列补全。 |
| 开标时间 | 开标/开启/电子文件解密时间；只在正文明确“截止=开启”时等同投标截止时间。 |
| 开标方式 | 显式开标方式；或正文明确的网上、远程、电子、平台开标/解密。 |
| 开标地点 | 开标/开启地点；电子开标可记录原文明确的平台。 |
| 招标人 | “招标人/采购人”联系方式段或项目业主；不要把发布平台或代理机构填入。 |
| 招标联系人、电话、邮箱、地址 | 优先取招标人段；仅在公告末尾联系方式段作回退。 |
| 招标单位 | 采购/招标组织单位或发布单位；若未出现则与招标人一致。 |
| 招标代理机构五字段 | 只从代理机构段提取；没有代理机构不要误填。 |
| 中标人、中标候选人、中标金额、中标公告时间 | 仅中标/成交公告提取。招标公告保持为空；废标公告可将中标人标为“废标”并记录废标原因。 |

## 常见输入列

- 正文可能被拆为 `正文`、`文本`、`文本1`、`文本2`。使用最长正文作为主体，并将其余短列作为补充上下文。
- `时间/发布时间/文本1` 可提供公告日期，`截止时间/投标截至时间/文本2` 可提供截止日期；应保留原文时间，不以采集时间替代。
- `发布单位` 是招标单位候选，不等同于招标人；优先级低于公告联系方式段的“招标人/采购人”。

## 质量检查

1. 每条均有原标题或可说明原始标题缺失。
2. 每条均有项目名称或保留其清理后的原标题。
3. 编号、项目规模、范围、工期、金额、时间均可追溯到源文/源列。
4. 来源链接缺失时明确标记为源数据未披露；不补造 URL。
5. 招标金额为数字字符串（元）或空；不得混入“万元”字样。
